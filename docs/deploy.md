# Развёртывание на сервере

Инструкция для того, кто будет обслуживать систему. Всё работает в Docker: приложение,
PostgreSQL, Caddy (HTTPS) и ежедневные резервные копии.

## 1. Требования

- Linux-сервер (Ubuntu 22.04+, Debian 12+ или аналог), 1–2 ядра, 2 ГБ памяти, 10 ГБ диска.
- Docker 24+ с плагином Compose: `docker compose version`.
- Один из вариантов доступа:
  - **публичный домен** (например, `tests.example.ru`), DNS-запись указывает на сервер, открыты
    порты 80 и 443 — HTTPS-сертификат Let's Encrypt Caddy получит и будет продлевать сам;
  - **сервер за прокси вуза**, который уже обеспечивает HTTPS, — тогда открыт только порт 80.

> Без HTTPS пароли идут по сети открытым текстом. Режим «только HTTP» допустим, только если
> HTTPS делает прокси перед сервером.

## 2. Установка

```bash
git clone https://github.com/viteax/competency-assessment.git
cd competency-assessment
cp .env.example .env
```

Заполните в `.env` три обязательных значения:

```bash
SITE_ADDRESS=tests.example.ru   # или :80 за прокси вуза
SECRET_KEY=...                  # python3 -c "import secrets; print(secrets.token_urlsafe(48))"
POSTGRES_PASSWORD=...           # любой длинный случайный, например так же через secrets
```

Права на файл: `chmod 600 .env` — в нём секреты.

## 3. Первый запуск

```bash
docker compose -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml ps      # все сервисы — running / healthy
```

`--build` собирает образ на сервере из исходников. Если образ опубликован в GitHub Container
Registry, можно не собирать: укажите в `.env` `APP_IMAGE=ghcr.io/viteax/competency-assessment:1.0.0`
и запускайте без `--build`.

Миграции базы применяются автоматически при старте приложения.

**Создайте администратора** (пароль спросит интерактивно):

```bash
docker compose -f docker-compose.prod.yml exec api python -m scripts.create_admin <логин>
```

Откройте `https://<домен>/` и войдите. Студентов удобнее всего загрузить во вкладке
«Импорт → Студенты»: система выдаст временные пароли, которые студенты сменят при первом входе.

> Демо-данные (`scripts.seed`) в продакшене загрузить нельзя — сервер откажется: у демо-учёток
> публичные пароли.

## 4. Проверка работы

```bash
curl -fsS https://<домен>/ready     # {"status":"ok","version":"1.0.0"} — приложение и база в порядке
curl -fsS https://<домен>/health    # процесс жив (базу не проверяет)
```

Для внешнего мониторинга (UptimeRobot, Zabbix и т.п.) проверяйте `/ready` раз в минуту.

## 5. Логи

```bash
docker compose -f docker-compose.prod.yml logs -f api      # приложение
docker compose -f docker-compose.prod.yml logs -f caddy    # прокси и HTTPS
docker compose -f docker-compose.prod.yml logs backup      # резервные копии
```

Логи приложения — JSON, по строке на запрос: метод, путь, статус, время ответа, пользователь,
IP и `request_id`. Если пользователь видит «внутренняя ошибка сервера, код запроса …», найдите
подробности по этому коду:

```bash
docker compose -f docker-compose.prod.yml logs api | grep <код>
```

Логи ротируются автоматически (до 5 файлов по 20 МБ на сервис). Действия пользователей
(кто что изменил) хранятся отдельно — во вкладке «Журнал» у администратора.

## 6. Резервные копии

Сервис `backup` каждый день в `BACKUP_TIME` (по умолчанию 03:30, часовой пояс `TZ`) делает
копию базы в `./backups/competency-ГГГГ-ММ-ДД_ЧЧММ.dump`, проверяет, что она читается, и удаляет
копии старше `BACKUP_KEEP_DAYS` дней (по умолчанию 30).

**Копия прямо сейчас** (например, перед обновлением):

```bash
docker compose -f docker-compose.prod.yml exec backup sh /usr/local/bin/backup.sh
```

**Храните копии не только на этом сервере.** Копии в `./backups` не спасут при поломке диска.
Настройте регулярное копирование папки на другой сервер или в хранилище, например:

```bash
# crontab -e на сервере: каждый день в 04:00 — на резервный сервер
0 4 * * * rsync -a --delete /path/to/competency-assessment/backups/ backup@other-host:/backups/competency/
```

**Восстановление** (заменит текущие данные; перед этим скрипт сам сделает свежую копию):

```bash
deploy/restore.sh backups/competency-2026-10-13_0330.dump
```

Раз в семестр проверяйте восстановление на тестовой машине — непроверенная копия может
оказаться бесполезной в нужный момент.

## 7. Обновление

```bash
cd competency-assessment
docker compose -f docker-compose.prod.yml exec backup sh /usr/local/bin/backup.sh   # копия
git pull
docker compose -f docker-compose.prod.yml up -d --build
```

При использовании готового образа вместо `git pull` и `--build` поменяйте версию в `APP_IMAGE`
и выполните `docker compose -f docker-compose.prod.yml up -d`. Миграции применятся при старте.
Что изменилось в версии — в [CHANGELOG.md](../CHANGELOG.md).

**Откат:** верните предыдущую версию образа (или `git checkout <тег>` и `--build`). Если новая
версия успела изменить схему базы, восстановите копию, сделанную перед обновлением.

## 8. Чек-лист безопасности

- [ ] Сайт открывается по `https://`, в браузере нет предупреждений о сертификате.
- [ ] `.env` с правами 600, не попадает в git и в общие папки.
- [ ] Открыты только нужные порты (80/443); порты базы (5432) и приложения (8000) снаружи
      недоступны — так настроено в compose, не меняйте.
- [ ] Администраторов — минимум, у каждого своя учётка (видно в журнале, кто что делал).
- [ ] Копии из `./backups` регулярно уходят на другой сервер.
- [ ] Обновления системы и Docker на сервере ставятся регулярно.

## 9. Решение проблем

| Симптом | Причина и решение |
| :-- | :-- |
| `api` перезапускается, в логах `задайте SECRET_KEY` | В `.env` нет `SECRET_KEY` или он короче 32 символов. |
| В логах `у демо-учёток публичные пароли` | В базу загружали демо-данные. Удалите учётки admin/student1–3 или смените им пароли (через dev-окружение) либо восстановите чистую копию. |
| Caddy не получает сертификат | DNS-запись не указывает на сервер или закрыты порты 80/443. Смотрите `logs caddy`. |
| `/ready` отвечает 503 | Приложение не достучалось до базы: `logs db`, свободное место на диске (`df -h`). |
| Пользователь: «несколько неверных паролей подряд» | Защита от подбора: подождать 30 секунд. Забытый пароль администратор сбрасывает во вкладке «Студенты». |
| Пользователя выкидывает на страницу входа | Сессия завершается после 60 минут без действий (`SESSION_IDLE_MINUTES`). |
